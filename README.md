# R10 修改器

独立的 Windows 桌面修改器，C# / .NET 10 / WPF，适配中文 BugFix 版《兰斯 10》。界面支持明暗主题、高 DPI、分类侧栏和窄窗口布局。

当前源码开发版本为 **0.5.0 / win-x86**；已交付的玩家包仍为 0.4.0，待本轮优化完成后重新发布。本仓库保存源码、测试和构建脚本，不包含游戏、存档或已生成的安装包；克隆仓库后需要自行构建。重要版本变化记录在仓库根目录 `CHANGELOG.md`，开发协作规则见 `AGENTS.md`。玩家包随附本 README。

接手开发先读仓库根目录 `HANDOFF.md`，了解当前交付、本机工作环境、验证证据及未完成事项；通用操作与构建方法仍以本 README 为准。

## 给玩家使用

解压 `R10Trainer-v0.4.0-win-x86.zip`，双击 `R10Trainer.exe`，保留解压目录里的全部文件。发布包自带运行时，玩家无需安装 .NET、Python、Codex 或 MCP。

1. 在修改器里点击“选择游戏”，选择自己的 `Rance10.exe`。
2. 退出游戏，点击“安装游戏组件”。修改器会验证版本，备份需要变更的文件，并安装随包提供的游戏组件。
3. 点击“启动游戏”，在战斗分类中开启“HP 保护”。在资源分类中可开启“随机掉落不重复”。其余功能也在同一界面使用。

游戏路径会保存到本机用户设置。发布包不带作者的路径、游戏本体或存档。修改器和游戏应使用相同权限级别；版本不匹配时禁止安装和写入。

HP 保护组件通过游戏的扩展入口参与伤害结算。它在已接入的伤害点保留我方原血量，不主动补满；治疗、开战初始化与指定的结果结算保持原有行为。组件安装后仍须在修改器中开启开关；关闭修改器会关闭本次由它开启的保护。游戏重启后默认关闭。

未安装新版组件时，HP 保护、随机掉落去重、食券重抽、自动战斗重配、资源及等级修改不可用，其余功能仍可使用。旧版组件请先“恢复游戏文件”，再“安装游戏组件”；不要手动覆盖备份目录。安装、恢复前都要退出游戏。“恢复游戏文件”使用本次安装的备份恢复原文件；文件被其他补丁改动时会拒绝覆盖并提示检查。备份目录 `.r10trainer-hp` 位于所选游戏目录内，请保留。安装保留原有游戏名称与存档位置，不直接编辑存档。

### 升级与恢复

1. 正常关闭旧修改器，让它完成开关关闭和临时补丁恢复，再退出游戏。
2. 将新版玩家包解压到新目录，启动新版修改器并选择原游戏目录。
3. 如果提示旧版组件，先点击“恢复游戏文件”，成功后再点击“安装游戏组件”，最后重新启动游戏。

安装会替换 `Rance10.ain`、修改 `AliceStart.ini` 的 DLL 加载项并添加 `R10Bridge.dll`；不会替换 `Rance10.exe`。恢复会还原本次安装前的 AIN、INI 并移除本次添加的 DLL，原备份归档为 `.r10trainer-hp.restored-<标识>`。目录名中的 `hp` 是沿用的备份格式，同时服务 HP 保护与掉卡去重。

要停用整个组件，正常关闭修改器、退出游戏后执行“恢复游戏文件”。确认恢复成功后，可移除解压的修改器目录。直接删除修改器目录不会卸载游戏组件；恢复也不会撤销已经写入存档的数值或领取的奖励。

本机设置位于 `%LOCALAPPDATA%\R10Trainer\settings.json`，演示模式使用独立的 `demo-settings.json`。窗口位置或路径设置异常时，可以先退出修改器、备份并重命名对应设置文件，再重新启动；这不会重置游戏存档。

### 常见问题

| 现象 | 处理方式 |
|---|---|
| 等待游戏或未连接 | 核对所选 `Rance10.exe` 目录与实际运行目录；修改器和游戏使用相同权限级别。开发副本与正常游戏是不同目标。 |
| 等待场景稳定、部分数值不可用 | 标题、读档和过渡场景可能没有完整游戏数据。进入适用场景后再操作，不以组件连接成功代替战斗就绪。 |
| HP 保护可用，随机掉落去重不可用 | 检查是否仍在运行旧版组件；退出游戏，恢复后安装新版组件并重启。 |
| 开启去重后画面里的卡片没变 | 开关只影响下一批奖励生成，不会重抽已展示的选项。 |
| 版本不支持、安装或恢复被拒绝 | 核对本文支持的文件指纹；保留提示和备份，不手动覆盖 `.r10trainer-hp` 或跳过哈希检查。其他补丁修改过目标文件时应先查清来源。 |
| 关闭窗口时提示恢复未完成 | 保留窗口，按提示重试。不要强制结束修改器或删除备份；无法确认状态时，退出游戏后再处理文件恢复。 |
| 游戏因组件异常无法启动 | 在游戏停止后，用修改器恢复游戏文件；若恢复也被拒绝，保留备份与完整错误文本再排查。 |

反馈问题时附上修改器版本、游戏版本、所在场景、复现步骤和完整提示；构建问题再附命令与相关错误段。可提供 `build-info.json` 中的版本、commit 和组件指纹，无需上传整份游戏、私人路径或存档。

## 功能

| 分组 | 功能 |
|---|---|
| 战斗 | HP 保护、敌人直死、敌人濒死、难度 |
| 战略 | 回合及锁定、累计人类死亡率及锁定、四国兵力及锁定、四国战果全满 |
| 资源 | 食券 / 金块、勋章、友情、资源全满、宝箱发现率加成、随机掉落不重复 |
| 成长与辅助 | 部队等级、角色★等级、食券重抽、自动战斗重配 |

共 18 项功能定义和 3 个独立锁。HP 保护、随机掉落去重、食券重抽、自动战斗重配、资源及等级修改由修改器直接连接游戏组件，其余功能继续使用经过版本验证的外部内存访问；所有功能只作用于所选游戏目录的进程。MCP 是开发调试工具，不参与玩家操作，也不包含在玩家发布包中。

- 资源全满：在游戏更新入口检查食券／金块、勋章、友情，仅对不足 3 的计数调用游戏 setter；保留正常消费和事件，下一次更新补足，关闭不回退已改数值。开启期间不可单独修改这三项资源。
- 数值：输入后按 Enter 或点击应用。失焦不提交，后台刷新不会覆盖正在编辑的草稿。
- 开关：“已应用”表示当前实现核对成功，不代表所有游戏场景均已实测。场景未就绪时暂停；敌人直死与濒死互斥。
- 锁定：保持当前值，四国兵力分别捕获四国数值。关闭只停止后续写入。
- 角色★等级：支持 10 / 40 / 80 / 200；确认后调用游戏的批量方法修改已创建角色并清空经验，下一级经验由游戏计算；超过游戏配置上限时整次拒绝。可能降级并影响继承。
- 随机掉落不重复：按当前存档的具体卡片 ID 排除已持有卡片，同角色不同版本仍可出现；同批随机选项去重，也避开该批指定卡片。固定奖励及餐券、经验提升等“拟态／”消耗型奖励保留原规则。仅过滤原有候选池，不绕过剧情、回合或稀有度条件；空池沿用餐券补位。开关对下一批奖励生效，已展示选项不重抽。临时批次记录在返回、读档时清除；未选卡片不会永久排除。
- 明暗主题、游戏路径和窗口位置保存在 `%LOCALAPPDATA%\R10Trainer`，不保存开启的修改请求。
- 演示模式：`R10Trainer.exe --demo`，可加 `--theme light` 或 `--theme dark`。只使用内置演示数据，不访问或启动游戏，不安装组件。

## 支持范围与限制

安装前按以下原始文件指纹识别：

| 文件 | SHA-256 |
|---|---|
| Rance10.exe | `39A508C05B13AFC5427F0B722FCE5C4EDECED126587E037D585CF0E70D279297` |
| Rance10.ain | `7ED22B2854DCB93B6E447198E7CB682CD05B90CF6AB3226091D80003D52DD48A` |

已安装组件的 AIN 还要核对解压后内容指纹 `7C674704D331F697339643A541958B259B8B7179D72346CA9C573F5A4B5829AF`。这样允许压缩库产生不同压缩字节，同时严格限定实际脚本内容。其他整合补丁不在当前支持范围。

- 回合只改变数值，不倒退剧情；资源、战果和等级修改可能随游戏保存，关闭修改器不会撤销已改数据。
- 宝箱功能是发现加成，不能保证掉箱；食券重抽不是正常消费免费；友情是可用次数，不是好感。
- HP 组件覆盖选定的伤害调用点；致死、毒伤、反射、简单战斗及其他章节尚未逐项实机验证，不承诺所有扣血路径均被保护。
- 外部内存功能的根链或对象变化会暂停写入并重新确认。接入组件后，读档代次或会话变化会取消回合、兵力和死亡率旧锁定，须确认新值后重新锁定；组件失联或心跳过期时暂停锁定。未接入组件时，沿用全部原地址的读档仍可能无法识别，应在读档前关闭锁定、读档后重开。特定结算阶段暂停死亡率写入。
- 食券重抽与自动战斗重配使用组件开关，关闭时恢复原游戏分支，无需扫描或修改运行中的 AIN 指令。旧外部补丁引擎保留作原版兼容代码与回归测试，不对新版组件脚本写入。
- AIN 定位分片扫描并显示进度，取消和关闭优先处理；扫描、数据维护与界面刷新分别调度。游戏布局变化时只重扫受影响区域。文件校验和区域枚举仍是同步操作，不承诺严格响应时限。
- 数据事务回滚不完整时停止此进程的后续数据写入，需重启游戏重新连接。跨进程写入与游戏执行并不构成原子事务。

## 开发与构建

需要 Windows、Git 和 .NET 10 SDK（`global.json` 固定 10.0.403，允许同一功能带的后续补丁）。建议在 PowerShell 7 中运行以下命令，工作目录为仓库根目录。首次还原需要访问 NuGet；发布包目标是 x86，即使开发机为 x64 也不要改为 AnyCPU。

只编译 WPF 界面、运行常规测试或演示模式，不需要游戏文件。构建组件另需：

- Python 3.11+，脚本仅使用标准库，无需安装 pip 依赖。
- MinGW 工具目录中的 `gcc.exe`、`ld.exe`、`dlltool.exe`、`as.exe`，支持 `-m32` 和 `i386pe`。
- 能处理 AIN 的 `alice.exe`；当前插桩按 alice-tools 0.13 CLI 校验，构建时使用 CP936 输入、UTF-8 输出。
- 本文指纹对应的原始 `Rance10.ain`，不能使用已经安装组件的 AIN 作为源文件。

这些工具不需要交给玩家。脚本的 MinGW 和 alice 默认路径属于原开发环境，换机器时必须显式指定自己的路径。

```powershell
# 首次获取源码（需要私有仓库访问权限）
git clone https://github.com/Misakura-R1n/R10Trainer.git
Set-Location R10Trainer

# 编译及常规自动检查，不启动或连接游戏
./scripts/build.ps1

# 只预览界面，不安装组件或读写游戏
dotnet run --project src/R10.App -c Release -- --demo

# 按自己的环境修改下列路径
$build = @{
    DotNetPath = 'dotnet'
    PythonPath = 'python'
    BridgeToolchain = 'C:\Tools\mingw64\bin'
    AlicePath = 'C:\Tools\alice\alice.exe'
    SourceAin = 'D:\Games\Rance10\Rance10.ain'
}

# 生成玩家组件、进行附加检查并发布玩家包
./scripts/build.ps1 @build -Bridge -Publish

# 另行发布助手使用的 MCP
./scripts/build.ps1 -DeveloperTools

# 构建带语义操作的开发组件与 MCP（不生成玩家包）
./scripts/build.ps1 @build -Controls
```

可用 `-DotNetPath`、`-BridgeToolchain`、`-PythonPath`、`-AlicePath` 指定本机工具路径。完成组件构建后可直接 `-Publish` 复用已核验的组件。玩家输出为 `artifacts/R10Trainer-v<版本>-win-x86/` 及同名 ZIP；开发 MCP 输出为 `artifacts/R10Developer/mcp/`。

玩家包中的游戏组件只包含自制 DLL 和小型 AIN 修改配方；安装时在玩家自己的 AIN 上应用配方，再核对完整结果。不分发生成后的完整 AIN、游戏资源或存档。配方目前只有 5888 字节的变更数据。原生 DLL 使用确定性 PE 时间戳，`build-info.json` 记录源文件和组件指纹。构建脚本不自动启动或修改真实游戏。

自动检查涵盖核心数据/补丁恢复、协议/统一运行时、原生组件、AIN 调用点、组件安装/恢复与副本准备。副本准备中的符号链接测试在缺少创建权限时显式跳过；真实游戏结果单独记录于上文。

### 检查与发布

| 入口 | 检查范围 |
|---|---|
| `./scripts/build.ps1` | 编译解决方案；核心逻辑、桥接协议及运行时、安装恢复的模拟或临时文件测试。 |
| `-Bridge -SourceAin ...` | 增加 x86 原生辅助进程、AIN 插桩、卡池字节码、副本准备、生成 AIN 兼容性和真实文件副本安装恢复检查。需要完整工具路径。 |
| `-Publish` | 增加核心 Win32 x86 辅助进程检查，生成自带运行时的玩家目录与 ZIP。依赖之前生成的玩家组件。 |
| `-DeveloperTools` | 发布 MCP 并检查 `initialize` / `tools/list`，不连接游戏。 |
| `-Controls -SourceAin ...` | 构建开发插桩与 MCP，检查原生辅助进程和 AIN 结构；卡池逻辑变更还应执行 `-Bridge` 的卡池检查。 |

测试项目是可执行检查程序，统一用构建脚本运行；只执行 `dotnet test` 不能代替上述检查。失败必须处理，跳过项要说明原因。只有文档改动时检查命令参数、路径、链接与 `git diff --check` 即可，不需要启动游戏。

发布时在 `src/R10.App/R10.App.csproj` 更新玩家版本，维护 `CHANGELOG.md` 的用户可见变化。修改过原生 DLL 或 AIN 插桩后，重新执行 `-Bridge`，再发布配方与 DLL 匹配的玩家包；不要复用旧 `artifacts` 冒充新构建。`-Controls` 的产物不用于玩家安装。

核对 `build-info.json` 中的版本、源码 commit、dirty 标记、源文件及组件指纹；干净提交构建便于追溯。发布脚本会覆盖同版本输出，保留旧包时应先确定新版本。玩家包必须保留 `bridge/`、运行时文件和 `licenses/`，不得加入 MCP、完整 AIN、游戏资源、存档或个人设置。仓库目前未设置开源许可证；发布玩家包不等于给源码指定开源许可。

### 准备实机副本

组件构建与发布不会启动游戏。实机测试先使用独立副本，避免正常游戏与测试进度共用存档。完成前面的 `-Controls` 构建后，可以准备一个全新的测试目录：

```powershell
./scripts/prepare-bridge-sandbox.ps1 `
    -SourceDirectory 'D:\Games\Rance10' `
    -TargetDirectory "$PWD\artifacts\control-game-test" `
    -SandboxName 'R10ControlTest' `
    -BridgeDirectory "$PWD\artifacts\bridge\controls" `
    -BridgeDll "$PWD\artifacts\bridge-controls-native\R10Bridge.dll"
```

源游戏必须符合原始指纹；目标须在本仓库 `artifacts` 下且尚不存在，不能放在玩家发布目录内。`SandboxName` 对应的整个存档目录也必须不存在，重复测试请使用新名称。脚本从 Windows 文档目录的 `AliceSoft/<原游戏名称>/SaveData` 读取原存档，也可用 `-SourceSaveDirectory` 指定；副本使用 `AliceSoft/<SandboxName>/SaveData`，保留原存档不动。脚本会复制文件、核对哈希并留下本地清单，不会启动游戏。

准备完成后，在确认本次实机测试范围后启动副本；MCP 的 `--game-dir` 只指向该副本。离线测试、辅助进程、界面模拟和实际战斗效果必须分别说明，不能互相替代。测试后的原文件校验依据副本清单中的原始哈希。

### 助手调试接口

MCP 为独立 stdio 程序，直接连接选定游戏的本机命名管道。`--game-dir <绝对游戏目录>` 可随游戏重启重新发现进程，也支持 `--pid <进程号>`。环境变量为 `R10_BRIDGE_GAME_DIR` / `R10_BRIDGE_PID`。当前 MCP 版本为 0.2.0。

语义操作需要 `controls` 开发插桩，`get_state.state.controlsAvailable` 必须为 `true`。`-Controls` 输出 `artifacts/bridge/controls/Rance10.ain`、`artifacts/bridge-controls-native/R10Bridge.dll` 和 `artifacts/R10Developer-controls/mcp/`。使用 `prepare-bridge-sandbox.ps1` 的 `-BridgeDirectory artifacts/bridge/controls -BridgeDll artifacts/bridge-controls-native/R10Bridge.dll` 参数准备全新测试副本。此配置只供开发测试，不作为玩家组件安装；玩家包仍使用 `full` 配方。不要把开发文件覆盖到 `.r10trainer-hp` 管理的安装目录。

```powershell
codex mcp add r10-bridge -- '开发输出目录\R10.Mcp.exe' --game-dir '测试副本的绝对目录'
```

| 工具 | 参数与行为 |
|---|---|
| `get_state` | 读取会话、心跳、读档代次、阶段、能力标记、HP 快照与拦截次数，以及去重开关、过滤候选数和餐券补位次数 |
| `set_feature` | 必填 `session`、`generation`、`feature: "hp_guard" / "no_duplicate_cards" / "food_redraw" / "auto_redistribute" / "resources_full"`、`enabled`；可选 `wait_ms`（0–5000） |
| `set_value` | 必填 `session`、`generation`、`feature`、`value`；支持 `food` / `medal` / `friendship`（0–3）、`unit`（0–999）、`star`（10/40/80/200）；可选 `wait_ms`（0–5000），要求 `dataAvailable` 与 `dataReady` |
| `get_command_result` | 用原始 `session` 与命令 `id` 查询结果 |
| `input` | `session`、`generation`、`action`；支持 `key`、`mouse_move`、`mouse_left`、`mouse_right`。按键用 `key`，鼠标用游戏画布坐标 `x: 0..1919`、`y: 0..1079`；`duration_ms: 30..2000`，默认 100 |
| `load_save` | `session`、`generation`、`slot: 0..9998`，可选 `wait_ms`。slot 是 `LocalSaveNN.asd` 的游戏内部编号，例如 `LocalSave5005.asd` 对应 5005；必须已存在，不创建或写入指定存档 |
| `end_turn` | `session`、`generation`，可选 `wait_ms`；只在活动战斗场景允许操作时，调用正常的结束回合处理 |
| `use_skill` | `session`、`generation`、`party_index: 0..6`、`skill_index: 0..1`，可选 `wait_ms`；复用游戏的技能可用性判断和 `OnClickSkill` 调度 |

`party_index` 是内部队伍编号：屏幕从左到右七个位置依次对应 **5、3、1、0、2、4、6**；`skill_index` 0/1 分别为上/下技能。空槽位、AP 不足、状态不允许或已经行动时拒绝使用。战斗操作还要求 `battleReady` 为 `true`，进入菜单、剧情或动画阻塞时不可强行执行。命令由持有当前场景的更新回调在游戏线程处理，后台管道线程不调用 VM；未处理命令在游戏线程恢复更新时按 3 秒期限拒绝。

`input` 通过 Windows 输入送达所选游戏窗口，会尝试激活窗口；最小化、焦点变化或鼠标目标被遮挡时拒绝/中止。坐标按客户区缩放，标准 16:9 游戏画面已实测，其他留黑边布局尚未验证。按下、保持和释放在一次有界调用内完成，取消时也尝试释放；不保留跨调用的长按状态。支持 Enter、Escape、Space、Tab、方向键、Shift、Control 和英文字母/数字，不开放系统组合键。返回 `source: windows_input`、`outcome: input_sent` 只表示输入已发送。单个 MCP 实例串行处理写操作；多个客户端或人工同时操作仍可能改变上下文。

先读取状态，再带会话和代次写入。普通读档与战斗重试会更新代次，旧指令被拒绝；游戏重启改变会话。`queued` 是排队，`applied` 仅表示游戏线程已执行开关或调用操作入口，不代表动画已经结束。读档会丢弃当前未保存进度；须再检查新的 `loadGeneration`、`lastCompletedGeneration` 和 `lastLoadOutcome: 1` 才能确认加载完成。发送后丢失回复时结果可能未知，应查询状态/结果，不自动重发。`effectVerification: not_verified` 区分执行确认和实际游戏效果。

开启组件功能前检查对应的 `hpGuardAvailable`、`noDuplicateCardsAvailable`、`foodRedrawAvailable`、`autoRedistributeAvailable` 或 `dataAvailable`，并确认游戏线程心跳有效；资源和等级另要求 `dataReady`。各项能力独立。`filteredCards` 统计排除的候选条目次数，不是不同卡片种类数；候选池内保留的重复条目用于保持原相对权重。`fallbackCards` 统计空池补位次数，计数属于本次游戏进程。

2026-11-08 在独立 `R10ControlSandbox` 副本中，通过 stdio MCP 验证了读取存档 5005、鼠标点击进入战斗、键盘 Enter 推进对话、技能实际造成伤害（首轮敌方 HP 9000 → 7284；最终发布程序复测为 9000 → 7860）、重复使用已行动角色被拒绝、结束回合后敌方行动和下一回合剧情。标题场景结束回合被拒绝，空队伍槽位、旧代次输入/读档及不存在的存档被拒绝。最终发布程序与更新后的原生 DLL 已重启复测。协议、输入、原生辅助进程和 AIN 的自动检查入口见上表；这些不能替代其他章节、特殊战斗和所有技能的实机测试。玩家包不依赖这些开发工具。

多个客户端共享组件开关；修改器退出时会分别关闭它在当前会话中开启的功能，可能覆盖其他客户端后来对同一开关的请求。仅由 MCP 开启而修改器未接管的保护，不因修改器退出关闭；需通过 MCP 显式关闭或退出游戏。

`ready` 表示游戏线程可处理命令，不保证处于战斗。标题和剧情对话期间 HP 快照可为 `null`。`frame` 记录更新入口调用次数，包含缩略图更新，不能视为渲染帧率。保留 `--bridge-game <绝对目录>` 作为开发启动参数，使用统一修改器界面。

### 架构与扩展

WPF 界面通过 `UnifiedTrainerRuntime` 使用统一的功能目录和状态快照。HP 保护、掉卡去重、食券重抽、自动战斗重配、资源及等级修改路由到游戏组件；其他功能路由到经过版本核验的外部内存引擎。组件缺失时不会把这些功能降级为轮询补血、事后改卡或运行时指令补丁。

玩家修改器和开发 MCP 都使用 `R10.Bridge.Client` 连接命名管道 `R10Bridge.<PID>`，核验服务端进程与会话。管道线程只接收有界消息和管理队列；游戏线程在已插桩的更新入口消费命令，AIN 脚本负责访问游戏对象。卡池去重在随机抽选前执行，批次开始时冻结开关，临时借用的批次数组仅在同步 `CreateCard` 生命周期内由脚本访问。读档使旧代次命令和临时批次失效。

采用 .NET / WPF 承载 Windows 桌面界面与 Win32 访问；x86 发布目标与当前游戏匹配。原生 DLL 和版本固定的 AIN 插桩用于必须参与游戏自身结算的功能。MCP 是同一组件的开发客户端，玩家版无需安装或启动它。

| 项目 | 职责 |
|---|---|
| `src/R10.App` | WPF 界面、游戏选择、组件管理、主题与关闭流程 |
| `src/R10.Core` | 版本验证、Win32 访问、对象定位、数据事务、脚本补丁与恢复 |
| `src/R10.Bridge.Install` | 小型配方应用、备份、安装、恢复与中断处理 |
| `src/R10.Bridge.Client` | 有界管道协议、服务端进程核验、会话与结果 |
| `src/R10.Bridge.Runtime` | 统一功能路由、状态合并、组件开关与独立关闭责任 |
| `native/R10Bridge` | 游戏线程命令队列、HP 过滤、卡片批次生命周期、读档生命周期、命名管道 |
| `src/R10.Mcp` | 仅供开发的 MCP 适配 |
| `scripts/bridge` | 固定版本 AIN 插桩、配方导出、离线校验、隔离副本准备 |
| `tests/` | 故障语义、组件恢复、协议与独立 x86 辅助进程检查 |

`prepare-bridge-sandbox.ps1` 保留为开发用副本脚本，目标只允许本仓库 `artifacts` 下的新目录，游戏名称对应的整个存档目录也必须全新，不用于玩家安装。AIN 分析基于字节码和函数元数据，不等于原始源码。原功能语义、布局与字节资料参照 Hanny 的 `82b06b1e283a80ce98aa1a1fe1796d8a2280f8af`；本项目独立实现，没有加载旧 Core.dll。

新增功能时先在 `src/R10.Core/Contracts.cs` 定义名称、分组和交互语义，再决定由外部内存还是游戏组件实现。组件功能同时维护原生能力位、客户端状态、运行时路由和各自的关闭责任；MCP 支持按开发需要添加，不作为玩家功能前提。AIN 插桩改变后同步更新版本指纹、安装配方及相关测试，旧版和未知版本必须明确拒绝。涉及写入的改动应覆盖目标变化、读档、失败恢复和关闭路径，再在隔离副本中验证实际效果。
